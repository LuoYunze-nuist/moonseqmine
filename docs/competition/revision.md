# 邮件复审修订记录

## 修订依据

本轮收到的初审邮件认为原项目的算法范围偏窄，建议补充 Top-K 或更完整规则，并与成熟实现进行正确性/功能对比。本文只记录本轮已经实现并可复现的技术修订，不把邮件意见改写成完整赛事章程，也不代表官方复审结论。

## 已实现

- 新增 `top_k` 公共 API，支持无位置约束下的精确支持度排行。
- 使用动态第 K 支持度阈值剪枝；支持度相等时继续探索，由 `pattern_key` 处理稳定并列。
- 增加参数错误测试、并列排序测试、可用模式不足测试，以及独立 powerset oracle 对照。
- 保留原有 `mine` 的 `max_gap`/`max_span` 语义和已有独立穷举测试，不将未经证明的约束行为改写为新语义。
- 在查重记录中补充 `top_k` 的行为边界复核：无位置约束、有限 `max_items` 模式族、支持度降序及稳定并列排序；不把相邻的 CEP、字符串子序列检索或无序闭包项目当作直接替代。

## 对标与边界

项目继续对照 Apache Spark PrefixSpan 的有序项集输入和序列支持度语义，并用 PrefixSpan-py 0.5.2 对标标量序列子集；差分脚本实际调用的是上游 `frequent(1)` 生成独立标量支持预期，再由本项目按公开的稳定排序规则核对 `top_k`，并非宣称上游提供同名 Top-K API。多项项集和位置约束由本项目自己的穷举 oracle 验证。项目没有实现 BIDE+、完整闭合序列算法、分布式 Spark runtime、实时 CEP 或统计显著性推断，因此申报与 README 只声明已实现的 Top-K 和既有有界闭合/极大后处理。
