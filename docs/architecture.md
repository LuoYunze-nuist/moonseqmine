# 算法与数据契约

数据库是记录数组，每记录为有序项集数组，每项集为严格递增的非负 Int32 标签。构造器复制并规范化，计算入口验证手工构造值。模式非空，空记录代表没有事件但仍参与支持率分母。

投影状态保存 `(sequence_id, first_position, last_position)`。从空前缀做 S 扩展；非空前缀可在末项集中追加更大的标签（I），或在后续位置追加一个单项集（S）。I 的严格标签顺序使每一模式只有一个构造路径。每个候选去重投影状态；支持度对序列 ID 去重，绝不按嵌入数计数。保留所有首末位置保证 gap/span 约束不会因只保留最早嵌入而漏解。前缀约束继承，故可以按前缀支持剪枝；不假设在最大间隔下删除任意中间项集后仍保持支持单调性。

挖掘最大 64 项以限制递归深度。投影的累计状态、扫描步骤和输出个数均有硬预算。超过预算不返回部分结果；API 不保证这些计数限制输入、候选排序或任意下游后处理的总资源。闭合/极大后处理复杂度为输入模式族的两两比较；调用方应控制族大小。

普通支持匹配用独立动态状态前沿；证据枚举遍历完整位置路径并验证位置严格递增。独立测试 oracle 枚举每条源记录的所有位置掩码和每项集的非空项子集，然后在记录内去重再汇总；与投影增长不共用核心递归。Python 差分只覆盖单元素项集，其上游不能验证本库 I-extension；该部分由穷举负责。

支持索引保存深拷贝数据库，用标签倒排集合交集减少候选；交集仍不足以证明共现或顺序，因此必须再做精确匹配。群组选择拒绝重复记录 ID，保留来源映射，避免无意加权支持。

编解码在数值词法层检查整数与边界，JSON 不经过浮点；SPMF 使用显式结束标志。标签映射从0开始，SPMF只支持正整数，两个格式的差异保留为显式错误。
